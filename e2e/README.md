# e2e（端到端测试）

真跑一遍「人能做的事」，而不是只检查某个函数返回值。
三条 spec 加起来 37 条断言，覆盖登录、上传、缩略图、分类筛选、灯箱、删除、移动端布局。

## 为什么要有这个目录

在这之前，项目里**一条能进仓库的自动化测试都没有**：66 个探针脚本全躺在
`.workbuddy/tmp/verify/` 里，而那个目录在 `.gitignore` 第 30 行被忽略掉了。
结果是：每次改完只能靠「我记得跑过」来保证没坏，换台机器就什么都没有。

这里只搬「最值钱的几条」—— 也就是一旦坏了、用户立刻能看见的那些：

| spec       | 验什么                                                         | 需要浏览器 |
| ---------- | -------------------------------------------------------------- | ---------- |
| `api`      | 登录鉴权、上传、缩略图生成/尺寸/体积、列表、分类精确匹配、删除 | 否         |
| `album-ui` | 后台选图上传 → 前台相册显示 → 切分类 → 灯箱看原图 → 删除       | 是         |
| `mobile`   | 390×844 下网格 2 列、格子正方形、无横向溢出、灯箱不出屏        | 是         |
| `live`     | 线上只读巡检（首页/路由/接口/图片可访问/未登录被拦）           | 是         |

## 前置条件

```bash
npm run backend   # 后端 :8000
npm run dev       # 前端 :5173
```

浏览器用的是**本机已安装的 Chrome**（`e2e/lib/cdp.mjs` 里自动找常见路径），
用的是 Chrome 自带的调试协议（CDP），不下载 Playwright 那几百 MB 浏览器。

## 怎么跑

```bash
# 本地全套（接口 + 浏览器 + 移动端）
ADMIN_PASS='你的密码' npm run test:e2e

# 只跑某一组
ADMIN_PASS='你的密码' node e2e/run.mjs api
ADMIN_PASS='你的密码' node e2e/run.mjs mobile

# 线上只读巡检（只发 GET 和一次错密码登录，不写不删）
ADMIN_PASS='你的密码' npm run test:e2e:live
```

PowerShell 里设环境变量是 `$env:ADMIN_PASS='你的密码'; npm run test:e2e`。

**密码故意没有默认值。** 这个仓库是公开的，把管理员口令写成代码里的默认值，
等于把线上后台的钥匙一起发布出去（而且登录接口目前没有失败次数限制）。

退出码：全绿是 `0`，任何一条失败是 `1`，spec 中途崩了也记成失败并以 `1` 退出 ——
方便以后想接 CI 时直接用。

## ⚠️ 它会写数据

`api` 和 `album-ui` 会**真的往库里传一张照片，跑完再删掉**。
不写就验不了上传链路，所以这是刻意的。也因此：

- 只对**本地**跑这套；
- 线上那条（`--live`）只读，绝不写；
- 跑挂了可能留下一条测试照片，手动在 `/admin/album` 删掉即可。

## 目录结构

```
e2e/
  run.mjs              入口：按顺序跑 spec、汇总、给退出码
  lib/cdp.mjs          起无头 Chrome + 连接 CDP + 轮询等待 + 塞文件
  lib/api.mjs          接口层小客户端（登录/上传/删除/下载）
  lib/png.mjs          在内存里造一张 PNG（不往仓库塞二进制测试图）
  lib/check.mjs        断言收集与汇总
  specs/*.mjs          具体用例
```

## 写新 spec 的几条规矩

1. **等条件，不要等时间。** 用 `waitFor(表达式)` 轮询到真，别 `sleep(1000)`。
   写死时长在本机快的时候白等、慢的时候偶发失败。
2. **期望值从实测来，别猜。** 断言里出现的数字（480、2 列、169px）都是量出来的，
   不是设计稿推算的。
3. **读图之前先等 `img.complete`。** 图没下完时 `naturalWidth` 是 0，
   直接读会把「正在加载」误判成「加载失败」（第 43 轮踩过一次）。
4. **判「文件真的没了」别用浏览器。** 图片刚看过就在 HTTP 缓存里，
   删除后浏览器照样可能回 200。要用 node 侧 `fetch(url, { cache: "no-store" })`。
5. **认领自己造的数据靠 id 差集**，别靠标题或「列表第一条」——
   表单里的标题可能是空的，排序规则也可能哪天改。
6. **断言函数的参数顺序是 `(id, 说明, 是否通过, 附加信息)`。**
   写成 `check('X', '说明', true)` 会让「说明」变成 `ok`（非空字符串恒为真），
   那条断言就永远 PASS 了 —— `lib/check.mjs` 会在类型不对时直接抛错挡住这种手滑。
