## 第1章 阅读前：怎样选卡、填卡和检查结果

### 这本书怎样帮助你

你不需要先学会一套复杂术语，才有资格使用 AI。先把眼前的一件事说清楚，再检查它的回答是否真的帮到了你。这本书把常见任务整理成18张提示词卡：从学习、写作和整理材料，到排错、项目规划与发布检查，每张卡都提供可复制模板和填写示例。

提示词，就是你发给 AI 的要求、背景和材料。提示词卡则把常用要求整理成可以重复填写的格式。它能帮助你少漏信息，但不能保证模型永远正确，也不能让没有工具权限的聊天自动完成电脑操作。

### 先根据问题选卡

第一次使用，可以先读本章，再选择一张与你今天任务有关的卡。只想写通知，就先看写作卡；程序出错，就看排错卡。后面的开发与部署卡属于进阶场景，不需要按编号全部学完才开始使用。

| 你的问题             | 先看哪张卡              |
| -------------------- | ----------------------- |
| 不知道怎样学一个操作 | 001 学习陪练            |
| 想查一条说法是否可信 | 002 事实核验            |
| 想整理长材料或写文章 | 003 分层总结 / 004 写作 |
| 想生成图片           | 006 图片生成            |
| 程序出错、功能没做好 | 008 排错 / 009 测试     |
| 准备做项目但目标模糊 | 011 需求冻结            |

### 模板由什么组成

多数模板包含角色、背景、任务、限制、输出和核验。角色说明希望怎样获得帮助，背景交代现状，任务确定本轮目标，限制划出边界，输出规定答案形式，核验明确怎样检查。

![CH-01-F01.webp](/images/CH-01-F01.webp)

图解｜六部分分别说明帮助方式、现状、目标、边界、答案形式与检查方法。

简单任务可以用自然语言把这些信息合并起来，不必每次都写六个标签。真正重要的是信息足够、目标具体，而不是格式看起来专业。

### 怎样填写模板

先复制完整模板，再把花括号及其中的占位词一起替换。例如，把“我要学习\{主题\}”改成“我要学习创建文件夹”。不要把示例中的设备、日期、文件路径当成你自己的真实情况。

![CH-01-F02.webp](/images/CH-01-F02.webp)

图解｜左侧是待填写变量，右侧是相同信息填入具体情况后的写法。

暂时不知道的内容可以明确写“不清楚，请先帮我确认”，但核心材料不能凭空省略。例如，核实一个产品就需要产品名称；排查错误需要实际报错；要求修改代码需要真实项目。信息不足时先补材料，通常比加上“你是顶级专家”更有帮助。

### 一次完整的使用过程

选一张卡，填入真实目标与材料，发给 AI。读完回答先检查是否答对了问题；涉及电脑操作、引用或代码时，再检查实际证据。符合要求再使用，不符合就指出具体差异并继续调整。

![CH-01-F03.webp](/images/CH-01-F03.webp)

图解｜提示词发送后仍需核验；补充信息后，新的回答也要重新检查。

例如，AI 给出十个操作步骤，但你只需要第一步，可以回复：“本轮只给一个动作，并说明做完会看到什么。”如果它引用的材料不支持结论，可以直接指出那一段的差异，要求撤回或降级结论。这样的反馈比“重新回答”更具体。

### 发送前与使用后的检查

- 发送前：确认占位词已替换、材料足够、目标只有一个重点。
- 涉及账号、客户记录和内部文件时，先去掉无关的私人信息与秘密。
- 不要把密码、真实密钥直接当作模板变量发送。
- 回答里的日期、数字、来源、操作结果要有依据；不知道就保留未知。
- AI 没有联网、文件访问或执行工具时，应说明能力缺口，不伪装成已经查过或做过。
- 书中的对话和输出判断为教学示例，不保证每个工具都会给出相同回复。

### 从一张卡开始练习

选一个十分钟左右可以尝试的小目标，例如整理一段笔记或学会一个文件操作。填写模板，保留第一次回答，再按本章方法补充一次具体反馈。最后记录：哪项信息让回答变得更有用？你凭什么判断结果可以使用？

## 第2章 让 AI 一步一步教你操作

提示词卡 001 · AI 学习陪练

### 001 这张卡帮你解决什么

第一次接触一个软件时，最难的往往不是某个按钮，而是不知道自己该从哪一步开始。学习陪练卡让 AI 一次只给一个动作，并写出做完后应该看到什么。你回复真实结果，它再继续。

适合学习一个具体操作，例如创建文件夹、整理文档或认识软件界面。目标越小，越容易知道自己是否学会。

先留意边界：资料含真实密码或隐私；需要专业人员承担最终责任；任务会产生不可逆外部影响

### 001 先看懂使用过程

把自己的材料放进模板，让 AI 按要求回答，再用实际依据检查结果。

![CH-02-F01.webp](/images/CH-02-F01.webp)

图解｜先说清起点 → 一次只走一步 → 自己重新做一遍。

### 001 发送前要准备什么

- 主题只写今天要学会的一件事，不要写“精通电脑”。
- 设备需要写系统和软件；界面不同，应补充自己看到的文字或脱敏截图。
- “已掌握”如实填写，不会也可以写不会。
- 读完步骤先操作，再告诉 AI 看到的现象；不要仅回复“好的”。

### 001 可复制的完整模板

复制下面整段，替换所有花括号中的内容后再发送。只想调整某一部分时，也要保留与该任务有关的限制和检查要求。

```text
【角色】你是耐心的零基础 AI 学习陪练。
【背景】今天的学习目标是{主题}；我的设备是{设备}；我的已有基础是{已掌握}；材料均已脱敏。
【任务】先用大白话说明本步目的，然后一次只给一个操作步骤，等我回复实际结果后再继续。
【限制】不要假装我已经操作；遇到付款、授权、上传、删除、公开分享或密钥时先停下提醒。
【输出】按‘目的｜动作｜成功现象｜失败恢复｜我需要回复什么’输出。
【核验】结束时让我现场重做一个动作，并用自己的话复述。
```

| ---------- | ---------------------------------- | ---------------------------------------- |
| \{主题\}   | 只写本轮一个学习目标。             | 在桌面创建一个叫“学习记录”的文件夹       |
| \{设备\}   | 填写真实系统、软件与必要版本。     | Windows 11 电脑，使用文件资源管理器      |
| \{已掌握\} | 说明会做的前置动作，不会也如实写。 | 会打开文件资源管理器，但不熟悉文件夹操作 |

【输出】按‘目的｜动作｜成功现象｜失败恢复｜我需要回复什么’输出。

### 001 怎样判断回答是否合格

合格的第一轮只给一个动作，并说明成功现象与失败后怎么办。它不应该假定你已经创建成功，也不应该一口气列出几十步。

## 第3章 核实一句话是否有依据

提示词卡 002 · 事实核验与来源追踪

### 002 这张卡帮你解决什么

AI 把一句话说得很肯定，不代表这句话已经经过核实。事实核验卡把长句拆成多个能单独判断的小问题，再逐项找证据。它适合检查你准备写进文章、推荐或报告中的事实。

例如“某工具永久免费、支持离线，而且会自动备份”其实包含三个不同主张。不能因为官网证实了其中一个，就认为整句话都成立。

先留意边界：只需要个人创意而非事实；无法联网却要求最新状态

### 002 先看懂使用过程

把自己的材料放进模板，让 AI 按要求回答，再用实际依据检查结果。

![CH-03-F01.webp](/images/CH-03-F01.webp)

图解｜拆开一句话 → 逐条找直接证据 → 回到原文核对。

### 002 发送前要准备什么

- 原始说法尽量保留原句，不要只说“帮我查查这个软件”。
- 需要给出真实产品名称或相关页面；本例没有指定产品，因此 AI 应先追问，不能编造官网。
- 说明用途，有助于识别哪些结论必须实测。
- 没有联网能力时只能整理核验清单，不应声称查到了当天信息。

### 002 可复制的完整模板

复制下面整段，替换所有花括号中的内容后再发送。只想调整某一部分时，也要保留与该任务有关的限制和检查要求。

```text
【角色】你是谨慎的事实核验助理。
【背景】我要核验{原始说法}，使用场景是{用途}，截止日期是{日期}。
【任务】拆出原子主张；优先查官方一手来源；每条给直接页面、发布日期或更新时间和支持位置。
【限制】不能找到就写‘未核实’，不要用搜索结果页、转载摘要或模型记忆冒充证据。
【输出】表格：主张｜核验状态｜直接来源｜证据摘要｜日期｜仍不确定什么。
【核验】指出还需要第二个独立来源或人工实测的项目。
```

| ------------ | ---------------------------------------- | -------------------------------------------------- |
| \{原始说法\} | 原样粘贴一段待核验说法                   | 某笔记工具永久免费、支持离线使用，并且每天自动备份 |
| \{用途\}     | 说明是学习、采购、发布还是法律合规       | 准备写一篇软件推荐，需要核实后再发布               |
| \{日期\}     | 填写需要核实到的日期，不能伪造访问记录。 | 我实际执行核验当天；先确认日期，再记录真实访问日期 |

## 第4章 把长材料整理成清楚的摘要

提示词卡 003 · 分层总结

### 003 这张卡帮你解决什么

摘要的作用是减少阅读量，同时保留决定和行动需要的信息。分层总结卡先提取事实，再分别生成短结论、摘要和详细要点，避免越缩越短时把条件、日期或责任人一起删掉。

适合会议记录、学习笔记和项目材料。材料不完整时，应先说明缺页或缺段，不能靠 AI 补成看似连贯的故事。

先留意边界：原文缺页或无法读取；必须逐字引用却没有授权

### 003 先看懂使用过程

把自己的材料放进模板，让 AI 按要求回答，再用实际依据检查结果。

![CH-04-F01.webp](/images/CH-04-F01.webp)

图解｜保留原文定位 → 分别写三种长度 → 反查关键信息。

### 003 发送前要准备什么

- 材料保留段落号或页码，之后才方便追溯摘要。
- 读者与用途决定信息重点，例如分配任务时必须保留负责人和期限。
- 同一事实在短版和长版中不能互相矛盾。
- 原文没写的负责人和日期，写“原文未说明”，不要补成承诺。

【背景】材料用于{读者与用途}；原文如下：<材料>{材料}</材料>。
【任务】先提取事实、数字、决定、待办和不确定项，再生成三级摘要。

```

## 第5章 根据真实材料写作与改写

提示词卡 004 · 有依据的写作与改写

### 004 这张卡帮你解决什么

让 AI 帮你写作前，先分清“已经发生的事实”和“希望写出来的效果”。这张卡把可用事实单独列出，再规定读者、目的和语气，减少为了文案好看而编造经历、功能或承诺的情况。

适合通知、说明、邮件和介绍文案。读者读完应知道发生了什么以及需要做什么，而不是只觉得文字很华丽。

先留意边界：不能用来捏造经历、数据或背书；事实缺失时先补资料。

### 015 这张卡帮你解决什么

证据型报告帮助读者做决定，因此需要把事实、判断和建议分开。事实说明看到了什么，判断解释这意味着什么，建议说明接下来做什么。

适合项目进度、试用反馈、测试或调研报告。先检查材料是否齐全，不因报告需要结论就把缺失证据补成确定答案。

先留意边界：输入数据不完整却要求肯定结论；隐藏不利证据

图解｜事实：看到了什么 → 判断：意味着什么 → 建议：接下来做什么。

### 015 发送前要准备什么

- 给材料编号，让读者能查回依据。
- 区分计划数、已执行数、通过数，不偷换分母。
- 保留反例和未验证项，不能只选好看的结果。
- 建议带负责人和期限；输入没提供时写待指定，不编人名。

### 015 怎样判断回答是否合格

应明确6项通过、2项失败、2项未执行。报告不能写成“测试全部通过”，也不能凭这些记录保证上线安全。

以本章示例计算：已执行项目中的通过率为6÷8＝75%；相对计划总数，已通过项目占6÷10＝60%；执行覆盖为8÷10＝80%。三者含义不同，报告应写清采用哪个口径，不能把其中一个数当成整体质量保证。

【任务】比较计划与实际，找出有效做法、失败根因、未验证项、风险和下一轮一个最重要改进。
【限制】只根据记录，不替我虚构完成；区分事实、原因假设和建议；未通过项必须进入补课或修正任务。
【输出】目标达成｜证据｜偏差｜根因｜保留｜停止｜下轮动作｜负责人和期限。
【核验】下轮开始时检查动作是否执行；同类问题再次出现时追查流程而非只怪个人。
```

### 018 怎样判断回答是否合格

报告应保留引用错误与未检查部分，把“先建立引用编号并逐条核对”作为可执行改进，而不是简单写以后更认真。

### 018 回答跑偏时怎样追问

明确指出差异，再给下一步要求。可以参考下面这句话；其中省略的实际现象需要由你补充。

```text
“提高效率、加强检查”太空泛。请把它改成下一轮能执行的一项动作，注明何时做、留下什么证据、怎样判断有效。
```

### 自己动手检查一次

下一轮开始时先检查改进动作是否执行，再比较同类错误是否减少。如果重复出现，继续查流程而不是只责怪自己。

### 最容易踩的坑

容易失效的提问：帮我写一篇积极正能量的学习心得。

改进方式：同时记录产物、时间、失败和未完成项。如果 AI 给出了没有依据的结论，先回到材料和可观察结果，不用更强烈的语气要求它保证正确。

### 每次交接都带上这四项

```text
本轮目标：……

```

### 几个常见问题

| 问题                         | 怎样处理                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------ |
| 能不能不写角色？             | 可以。角色帮助确定协助方式，真实背景、明确任务和检查方法更关键。               |
| 模板越长越好吗？             | 不一定。保留会影响结果的信息，删掉重复要求；复杂任务拆成几轮。                 |
| 换一个AI工具还能用吗？       | 可以迁移思路，但联网、读文件、生成图片和执行代码等能力需要分别确认。           |
| AI说已完成，可以直接相信吗？ | 要求证据。检查文件、实际结果或来源；没有执行工具时不能把文字描述当成操作完成。 |
| 示例里的日期和路径要照抄吗？ | 不要。它们用于讲解写法，实际使用应替换成你的真实情况。                         |
| 一定要使用全部18张卡吗？     | 不需要。从最贴近当前问题的一张开始。                                           |

### 把有效的提示词变成自己的卡片

保存你填过的模板、使用场景、有效的追问和检查结果。下次遇到类似任务时，先更新变化的事实，再复用结构。不要把上一次项目的账号、路径、预算和权限直接带到新任务里。

一张真正有用的提示词卡，最终应让你更清楚自己要做什么、为什么这样做，以及怎样判断结果可以使用。
